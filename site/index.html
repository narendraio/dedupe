Noisy logs in.Signal out.

dedupe is a tiny CLI filter that collapses repeated and near-duplicate log lines in a live stream. The 248th identical db timeout becomes a counter, and the one line that matters stays on screen.

01 what it does

Every kind of line, once.

Timestamps, ids, IPs and numbers change on every line. dedupe masks them, and lines that are left looking the same become one row with a counter.

near-duplicates, caught

Not just identical lines. timeout after 3057ms and timeout after 3102ms are the same event, so they’re one group.

live, in place

On a terminal, repeats bump a ×248 badge and a “last seen” label on the existing row instead of scrolling it away.

safe in pipes

Redirect to a file or pipe into grep and it switches to a plain stream that never rewrites a byte.

recipesworks with anything that prints lines

  • tail -f app.log | dedupelive, in-place counters
  • kubectl logs -f deploy/api | dedupesame thing, for pods
  • dedupe app.logread files directly
  • dedupe --summary app.log > /dev/nulljust tell me what’s loud
  • docker compose logs -f | dedupe --no-liveplain stream, safe for pipes
  • journalctl -f | dedupe --window 30s > quiet.loga quieter log file

04 flags

Seven flags. Zero config.

Flags can go before or after file names. Use - as a file name to read stdin.

flagdefaultwhat it does
--window5s

Pipe mode: a group ends, and its ↳ repeated N more times line is written, after this long without repeats.

--live-rows20

Live mode: how many recent groups keep updating in place. Capped to your terminal height.

--no-livefalse

Never redraw in place. Print a plain stream even on a terminal.

--summaryfalse

At exit (EOF or Ctrl-C), print the top 10 groups to stderr.

--keep-quotesfalse

Don’t replace quoted strings with "…".

--colorauto

auto, always or never. auto respects NO_COLOR and TERM=dumb.

--version—

Print the version and exit.

05 how it works

Two modes. It picks.

If stdout is a terminal you get live counters. If it’s a file or a pipe, you get a plain stream. --no-live forces the plain one.

  1. 01readany line length, any encoding
  2. 02fingerprintparallel across cores
  3. 03groupsame fingerprint, same row
  4. 04renderlive, or pipe

live modestdout is a terminal

Every new kind of line prints once. A repeat bumps the existing row’s ×N badge and its “last seen” label, in place. The newest 20 groups stay live; older rows freeze with their final count and scroll up like normal output.

2026-09-27T12:04:00Z INFO  server listening on :8080
2026-09-27T12:04:01Z ERROR db: query timeout after 3057ms (conn=31)  ×248 · just now
2026-09-27T12:04:05Z INFO  healthcheck ok  ×38 · 4s ago
2026-09-27T12:05:33Z ERROR payment provider returned 503 for charge ch_67ee87

pipe modefile, pipe, or --no-live

Nothing is ever rewritten. The first line of a group is written immediately. Once the group has been quiet for --window, or at end of input, one summary line follows.

07 questions

Frequently asked.

Will dedupe hide a line I need?
No. The first line of every kind is always printed verbatim. Repeats become a counter on that line (live mode) or one “repeated N more times” summary (pipe mode). Nothing is dropped silently.
How is this different from sort | uniq -c?
uniq only merges identical, adjacent lines, and sort needs the whole input first. dedupe works on a live stream, keeps the original order, and treats lines that differ only in timestamps, ids, IPs or numbers as the same event.
Does it understand JSON and logfmt?
Yes. JSON keys are never replaced, and neither are the values of msg, message, error, level, event, reason, status and a few other telling keys. {"msg":"db timeout"} and {"msg":"disk full"} stay apart.
Two different errors got merged. Now what?
If the difference lives in a quoted value, pass --keep-quotes to treat every quoted string as significant. Free-standing quoted phrases like "Observed a panic" are already kept.
Is it safe in pipes, files and CI?
Yes. When stdout isn’t a terminal (or with --no-live) it never rewrites anything, so grep, files and CI logs see a clean stream.
Does --window use the timestamps in my log?
No. Pipe mode uses wall-clock time, so --window is about how fast lines arrive, not the timestamps inside them.
What about stack traces?
dedupe compares lines, not multi-line records, so stack traces collapse frame by frame, which is usually what you want anyway.
Is it free?
Yes. MIT licensed, one binary, no account, no telemetry. Bugs and ideas are welcome as GitHub issues.
